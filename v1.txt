# 项目文档：随机提问与世界观生成器

> 本文档面向 AI Agent，提供完整、精确、可执行的规范。阅读后，Agent 应能**独立生成一个工程化、可维护、简洁、鲁棒、有审美**的 Web 应用，用于随机生成问题、根据回答长度触发不同风格的回复。

---

## 一、项目概述

### 1.1 项目名称
**EchoPrompt** —— 随机提问与诗意回响工具。

### 1.2 核心功能
- 随机展示一个**开放式问题**（来自内置问题池），激发用户思考和写作。
- 用户输入回答（文本域），点击提交。
- **根据回答字符数**决定输出：
  - **回答长度 > 30 个字符**（中文字符计为 1，英文/数字同样按字符数）  
    → 生成一段**世界观设定**（基于用户回答中的关键词、情绪、意象），长度约 80～150 字，风格接近“轻小说设定集”或“奇幻场景描述”。
  - **回答长度 ≤ 30 个字符**  
    → 输出**两句话的简短回复**，必须遵循严格的文学风格要求（详见下文 4.4 节）。
- 用户可以**继续提问**（重新随机抽一个新问题），或**再次就同一个问题作答**。
- 所有对话历史（用户问题和每次的回答+回复）保存在本地 `localStorage` 中，可查看历史记录。

### 1.3 非功能性目标
| 目标 | 具体要求 |
|------|----------|
| 工程化 | 使用 Vite + TypeScript，模块化，环境变量管理，ESLint + Prettier，Husky + lint-staged |
| 可维护 | 清晰目录，单一职责组件，纯函数工具，类型完备（无 `any`） |
| 简洁 | UI 极简：一个中央卡片，问题区、输入区、回复区依次排列，无冗余元素 |
| 鲁棒 | 输入防抖、字符数实时提示、localStorage 异常降级、错误边界、XSS 防护（React 默认转义） |
| 有审美 | 深色/浅色主题自适应，微交互动画，优雅字体（`Inter`），柔和阴影，留白舒适，回复区支持星号 `*emphasized*` 渲染为斜体或加粗 |

## 四、核心逻辑规格

### 4.1 问题池（`utils/questionPool.ts`）
至少包含 10 个开放式问题，例如：
```typescript
export const questionPool: string[] = [
  "如果你可以改变过去的一个决定，那会是什么？",
  "你最近一次感受到真正的平静是在什么时候？",
  "描述一个让你感到自由的小瞬间。",
  "如果你是一座城市，你会是哪座城市？为什么？",
  "什么东西是你曾经相信，但现在怀疑的？",
  "你希望未来的历史书如何描述这个时代？",
  // ... 共 10+ 个
];
```
随机选择使用 `Math.random`。

### 4.2 字符数判断与回复分发
- 用户输入 `answer`（字符串，已 `.trim()`）。
- 计算长度：`answer.length`（中英文均按 UTF-16 码元，中文字符长度 1，符合直觉）。
- **条件**：`length > 30` → 调用 `generateWorldview(answer)`  
- **条件**：`length <= 30` → 调用 `generateShortReply(answer)`

### 4.3 世界观生成（`generateWorldview`）
由于不依赖外部 LLM，采用**模板 + 关键词提取**的规则生成，确保输出稳定且可控。
- 提取用户回答中的**名词**（简单分词：按空格/标点拆分，取长度>1的词，或预设词库如“雨”、“城市”、“风”、“孤独”），若无则使用默认词“回声”。
- 使用三个模板之一随机选择，填充提取到的关键词。
- 输出长度控制在 80~150 字。
- 示例模板：
  > “在【关键词1】与【关键词2】的交界处，世界从未静止。你说出的每个字都落入地层深处，成为未来考古学家挖掘的星图。那里没有时间，只有【关键词1】缓慢的褶皱。”
- 要求：世界观需与用户回答有**语义关联**（至少包含用户回答中的一个名词或情绪词），避免完全无关的套话。

### 4.4 短回复风格规范（≤30 字符时）
**必须严格遵守以下文学风格**，不可使用常规聊天回复。风格要点：
1. **第二人称**“你”。
2. **疏离宏大的泛神论视角**：让自然/城市拟人化（雨、砖墙、海风、桥、路灯）。
3. **冰冷诗意的通感**：将个体的疲惫/渺小与城市/气候的庞大记忆混合。
4. **星号强调**：用 `*词句*` 表示重读或情绪锚点。
5. **粗粝口语**：可用“得了吧”、“无非是”、“也就那么回事”。
6. **陌生化比喻**：打破常规联想，如“疲惫像一片旧报纸贴在鞋底”。
7. **理想主义追问**：结尾用一个反问或微小宣言。

**示例**（固定输出时可以从以下池中随机选择一条，或根据用户输入中的关键词微调）：
- “*雨水*在敲每扇窗，砖墙记得所有被删掉的句子。你吞回喉咙的那半句话，无非是海风在防波堤上磨出的*盐粒*。可你真的甘心让这座城市独自老去？”
- “路灯亮起不是因为夜晚，而是因为有人还在走路。*疲惫*不过是行道树在风里数落叶 —— 世界不需要你立刻给出答案，*它只是想知道你还在听*。”
- “你盯着屏幕，屏幕也在盯着你。那些短促的叹息被空调吸走，变成云。*你问意义？* 桥从不问自己为什么跨在河上。*走吧，下一个问题会烫一些*。”

要求 **至少内置 5 条不同短回复**，随机返回一条。最好能根据用户输入中出现的字眼（如“累”、“没意思”）进行简单匹配，选择更贴切的那条。

### 4.5 历史记录数据结构
```typescript
interface ConversationEntry {
  id: string;           // uuid
  timestamp: number;
  question: string;
  userAnswer: string;
  response: string;     // 生成的回复（世界观或短句）
  answerLength: number; // 用户回答的实际长度
}

type History = ConversationEntry[];
```
持久化 key: `echoprompt_history`，最多保留 50 条，超出则删除最旧的。

## 五、UI/UX 与审美要求

### 5.1 布局
- 页面背景：浅色 `#F5F3EF`，深色 `#1A1A1A`。
- 中央卡片：最大宽度 `720px`，背景半透明磨砂玻璃效果（`backdrop-blur-sm`）或纯白/深灰卡片，`border-radius: 32px`，内边距 `2rem`。
- 问题区：字体 `serif`（如 `Crimson Pro`），字号 `1.75rem`，行距舒适。
- 输入区：`textarea` 宽度 100%，最小高度 120px，圆角，聚焦时发光。
- 实时字符数：显示在输入框右下角，颜色动态（<30 为橙色，≥30 为绿色）。
- 回复区：背景微淡灰色/半透明，内边距，斜体或正常体，星号内的文字自动渲染为 `font-style: italic` 且颜色为次要色（如 `#D97706`）。
- 历史记录：可折叠侧边栏（桌面）或底部抽屉（移动），显示每条的问题前 20 字 + 回答长度标记。

### 5.2 交互与动画
- 点击“新问题”按钮：随机抽取问题，清空输入框和回复区，保留历史。
- 点击“提交回答”按钮：若有输入，触发回复生成，保存当前对话，滚动到回复区。
- 按钮悬浮：轻微放大 `scale-105`，过渡 `0.1s`。
- 回复出现时：淡入向上滑动动画（`fade-in-up` 0.3s）。
- 历史记录项悬浮：背景变化。

### 5.3 响应式
- 手机：卡片内边距 1rem，问题字号 1.25rem，按钮纵向排列。

## 六、鲁棒性要求

1. **输入清理**：用户输入 `answer` 在存储和显示时不必转义（React 安全），但要防止空字符串提交（提示“回答不能为空”）。
2. **长度计算**：`trim()` 后计算，若长度为 0，不触发生成，显示提示。
3. **本地存储失败**：`try-catch` 读取/写入，出错时在控制台警告并提供内存存储回退（但提示用户“历史记录无法保存”）。
4. **错误边界**：若回复生成函数抛出异常，显示友好错误信息并回退到一条默认回复（如“世界打了一个嗝，再试试？”）。
5. **性能**：输入框防抖（`debounce` 300ms）仅用于字符计数显示，提交操作无防抖但需防止重复提交（提交后禁用按钮 1s）。

## 七、测试要求

### 7.1 单元测试
- `responseGenerator.ts`：
  - 输入长度 >30 的字符串，确保返回的世界观包含至少一个用户输入中的词（或满足长度范围）。
  - 输入长度 ≤30，确保返回的短回复符合风格清单（至少包含一个 `*`，调用后种类有限）。
- `questionPool.ts`：随机抽取不抛错，且所有元素非空。
- `storage.ts`：读写 `localStorage` 的模拟测试。

### 7.2 组件测试
- `AnswerInput`：显示实时字符数；提交按钮在字符数为 0 时 disabled。
- `ResponseDisplay`：正确渲染星号为斜体；正确区分世界观/短回复样式（可加微标签）。

### 覆盖率目标：核心工具 100%，组件核心交互 80%。
